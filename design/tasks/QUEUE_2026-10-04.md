## C · COLD START — "watch me do this"
Goal: start learning a workflow from a goal sentence + a few demonstrations on ANY web page, with no hand-written pack.
Owns: new `backend/shadow/onboard.py`, new `backend/tests/test_onboard.py`, new `backend/shadow/static/observe.js`,
new `backend/shadow/packs/custom/` (generated task definitions land here).
1. `observe.js`: a generic page observer (no app cooperation needed). Discovers inputs/selects/textareas/checkboxes
   and buttons; infers a stable name + human label (label[for], aria-label, placeholder, nearest heading/legend);
   reports `{type:"observe", fields:[{name,label,kind,value_kind,options}], url, title}` on load/route change,
   `field_changed{field,before,after}` with values for selects/checkboxes/numbers/short codes only (free text →
   length only; never passwords/hidden/credit-card/iban-looking inputs), and `action{name,label}` on button clicks
   (e.g. "Approve", "Reject", "Send"). Exposes `window.shadowObserve = {snapshot(), on(fn)}`. No UI, no network —
   the host script decides where events go.
2. `onboard.py`: `propose_task(goal: str, demos: list[Demo]) -> TaskDefinition` where a Demo is the observed field
   snapshot + changes + the final action. Uses `llm.parse(TaskDefinition-like schema, ...)` with the prompt from
   `taskdef.propose_taskdef_prompt`, then validates and repairs (unknown fields dropped, options merged from what was
   observed, action severity defaulted). Also `infer_without_llm(goal, demos)` heuristics (decision fields = fields
   whose final value varies across demos; actions = buttons pressed last) so it works offline and in tests. Save as
   `packs/custom/<slug>.json` with a version. `demos_to_cases(task, demos)` maps demos to cases for the engine.
3. Describe for Claude the API (`POST /api/onboard {goal, demos}` → task + a capture session on that pack) and the
   engine/main changes needed.
Acceptance: tests with a fake LLM and with `infer_without_llm` on 3 synthetic demos of a "support ticket escalation"
form: the produced TaskDefinition loads in `GenericPack` and a `Session` runs predict→gap on a 4th demo.
