## T1 · COACH — proactive tutor logic (pure module, not wired in)
Today the tutor only reacts (blocks a bad save). Build the logic for a trainer that coaches before mistakes.
Files: `backend/shadow/coach.py`, `backend/tests/test_coach.py`.
Read: `backend/shadow/engine.py` (tutor section: `tutor_open`, `before_save`, `_bkt`, `tutor_report`),
`backend/shadow/workmap.py` (`run_map`, `check_proposal`, Rule/Guardrail), `backend/shadow/packs/ap_invoices/__init__.py`.
Provide pure functions (no I/O, no LLM):
- `next_case(map, pack, mastery, seen_ids, candidates) -> case`: curriculum — pick the unseen case that exercises the
  weakest-mastery trusted rule (interleave; guardrails first when mastery < 0.5).
- `brief(map, pack, case, mastery) -> dict`: pre-case coaching: which fields matter here (from rules that fire or
  nearly fire), a predict-first prompt ("What would you code this to, and why?"), and whether to show a worked example
  (mastery < 0.3 → show the expert's quote + screen moment of that rule).
- `hint_ladder(map, pack, case, booking, action, level) -> dict`: level 1 = which field to look at, 2 = which rule
  applies (title), 3 = the expert's own words, 4 = the answer. Never reveals more than the level asks.
- `fade(mastery_p) -> "coach"|"check"|"silent"`: how much to intervene (silent only for non-guardrails ≥ 0.85).
Acceptance: `cd backend && .venv/bin/pytest -q tests/test_coach.py` ≥ 15 tests incl. a full simulated trainee run on
`PACK.demo_cases()["tutor"]` + `PACK.generate_cases(20)` showing hints escalate and fade.
